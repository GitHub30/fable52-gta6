# 実用性の分析

2026-11-20 時点の main（00b175a）を対象に、「遊べるか」「届けられるか（配信・性能）」「続けられるか（保守性）」「公開して問題がないか（権利面）」の 4 つの観点で評価したものです。ビルドとコードは実際に確認しています。

## 総評

| 用途 | 評価 | 理由 |
|---|---|---|
| 技術デモ・ポートフォリオ | **高い** | 実データの地図生成、自前の物理と描画、ブラウザで即起動。完成度が高く、見せやすい |
| 地図生成パイプラインの再利用 | **高い** | `tools/fetch_osaka.py` で範囲を変えれば別の街を作り直せる |
| ゲーム製品として | **中〜低** | 遊びの幅は広いが浅く、繰り返し遊ぶ理由が弱い |
| 一般公開・配布 | **要整理** | 実在のブランドや音源などの権利面が最大のボトルネック |

---

## 1. 遊べるか（ゲームとしての実用性）

**強み**

- 車、ヘリ、旅客機、列車、4 種の武器、手配度と警察、天候、昼夜と、サンドボックスの要素が一通り揃っている。
- タッチ操作、全画面、オートセーブがあり、「開いてすぐ遊べる」ための作り込みが丁寧。

**弱み**

- 続けて遊ぶ動機が弱い。ミッションは 5 種類で物語や連続性がなく、収集要素は隠しパッケージ 12 個だけ。
- 照準が水平方向にしか撃てず、車内からも撃てない（[ROADMAP.md](ROADMAP.md)）。戦闘が主要な遊びなのに制約が大きい。
- **難易度と操作感を実際に遊んで確かめていない。** [SPRINT_LOG.md](SPRINT_LOG.md) によると、ミッションのクリアは「瞬間移動テスト」での確認で、実機の FPS、マウスのポインターロック、音も耳で聞いていない。ここが「遊べる品質か」を判断するうえで一番の空白。
- 信号機がなく、高架や駅舎もない。大阪らしい景観の再現は地面と配置が中心。

## 2. 届けられるか（配信・性能）

- 依存は `three` だけで、`npm run build` は型チェック込みで成功した（271ms）。GitHub Pages への自動デプロイもあり、配信の仕組みはシンプルで良好。
- **初回ロードが重め。** `dist` は合計 **13MB**。
  - JS は 1 ファイルで 915KB（gzip 後 260KB）。800KB を超えたというビルド警告が出ている。
  - 主な大物は航空写真 `ground.jpg`（2.3MB）、人物モデル（約 2.7MB）、BGM `vietjet.m4a`（3.2MB）。
  - BGM は搭乗時にだけ読み込む作りで、ここは正しい。人物とサイレンも遅延読み込みにすれば、モバイル回線での初回起動を短くできる。
- 画質プリセット（low / high / ultra）と適応解像度があり、端末ごとの性能差への備えはある。ただし実機で FPS を測っていないので効果は未確認。

## 3. 続けられるか（保守性）

- 約 11,400 行の TypeScript で、[ARCHITECTURE.md](ARCHITECTURE.md) がモジュールごとの役割を細かく書いている。規模の割に読みやすい構成。処理の流れは [FLOWCHART.md](FLOWCHART.md) に図がある。
- 一方で `Game.ts`（1,233 行）にゲームの進行がまとまっていて、機能を足すほど肥大化しやすい。
- **自動テストがない。** ROADMAP の 7 番に Playwright による回帰テストが挙がっているが、まだ手つかず。物理や AI の調整で何かが壊れても気づけない。
- README に前のマップ（VELA BAY）の記述が残っている。「南・東のビーチ」「島に 12 個」とあるが、大阪のマップには該当する場所がない。
- 分析時点で、作業ツリーの `package-lock.json` が 30 行ほど削れた状態だった。このままコミットすると、CI の `npm ci` が失敗するおそれがある。

## 4. 公開して問題がないか（権利面）

公開・配布を考えるなら、ここが最も重要。

- **実在のブランドを使っている。** Vietjet の塗装と文字（`vietjetAir.com`）、JR 西日本「はなあかり」、36 チェーンの店名と店構え、プリウス・アルファード風の車、陸上自衛隊の 16 式、航空自衛隊の UH-60J、大阪の消防の文字。
- **実在の企業や組織を、犯罪と暴力のゲームに登場させている。** 車両強盗や警官への発砲といった遊びと、実名の店舗・鉄道・航空会社が同じ画面に並ぶ組み合わせは、権利者が特に嫌がりやすい。
- **音源の出典がリポジトリに書かれていない。** `vietjet.m4a` とサイレン 4 種（`public/sirens/`）。
- **リポジトリ名と公開 URL に「GTA6」が入っている**（`fable52-gta6`）。他社の商標。
- 地図データの出典表記（OpenStreetMap の ODbL、国土地理院）はきちんと書かれている。

個人で非商用に遊ぶ範囲ならリスクは小さいが、広く公開したり収益化したりするなら、実名のブランドを架空の名前に置き換え、音源の出典を確認してリポジトリ名を変える必要がある。

## 優先して取り組むなら

1. **権利面の整理**：ブランドを架空の名前にし、音源の出典を確認し、リポジトリ名を変える。公開を続けるなら最優先。
2. **実機での通しプレイ**：FPS、操作感、難易度、音を確かめる。「遊べるか」を判断する材料がまだない。
3. **Playwright の回帰テスト**：既存の `Game.debugStep` を使い、手動で行った検証の手順をスクリプトにする。
4. **初回ロードの軽量化**：JS のコード分割と、人物モデル・音の遅延読み込み。
5. **遊びの深み**：上下方向の照準、連続するミッション。
